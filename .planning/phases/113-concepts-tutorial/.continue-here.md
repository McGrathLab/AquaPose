## Critical Anti-Patterns

| Anti-pattern | Severity | Why |
|---|---|---|
| Fabricating or placeholder-ing a plausible-looking DOI in the tutorial or deposit README | blocking | D-21 requires `grep -q 'doi\.org' docs/getting-started/tutorial.md` to FAIL. A reader who follows a dead DOI link loses trust in every verified number on the page. |
| Regenerating `aquapose-tutorial-data/reference_outputs/` | blocking | Fenced by the Phase Boundary; Phase 111 delivered them and they verify clean. D-20 depends on them staying pre-smoothing. `git diff --stat` on that directory must be empty. |
| Editing a deposit file in the tree without the same edit in its `scripts/package_tutorial_dataset.py` template (or vice versa) | blocking | D-06. Fixing one home leaves the other to silently reintroduce or retain the error. This is why `TestDepositDocCorrections` exists. |
| Uploading any file not in the 22-entry `checksums.sha256` manifest | blocking | The verification run writes ~600 MB of LUTs and a `runs/` dir *inside* the deposit, and `write_checksums` walks with `rglob`. Derive the upload list mechanically, never by hand. |
| Marking `DATA-03` complete before the record is actually published | blocking | Phase 113 deliberately does not satisfy it (D-21). |
| Running `hatch env create` / `env prune` / `env remove` | blocking | The cu121 pin removal (D-08) only takes effect on next env creation. The current env has working CUDA (`torch 2.5.1+cu121`); recreating it may silently yield CPU-only torch. |
| Trusting a docstring or planning doc over source | blocking | Four separate claims in this phase were false when checked against code — see `<context>`. Read the implementation. |
| Using bare `pytest -k` instead of `hatch run test` | blocking | Bypasses the `@slow`/`@e2e` exclusions and pulls in GPU/data-dependent tests that take minutes. |
