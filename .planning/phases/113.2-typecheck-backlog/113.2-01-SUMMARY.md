## Decisions Made

- **Helper API and placement match the plan's `<design_decisions>` exactly** — `src/aquapose/core/h5.py`, two functions, `h5py.Group`/`h5py.File` parent, slash-path key, return type stops at `h5py.Dataset`/`h5py.Group` (never an array type, since h5py ships no `py.typed` marker).
- **Identity test corrected from `is` to `==`/`.id ==`.** While writing the RED test I asserted `result is expected` per the plan's "returns that Dataset unchanged (identity, not a copy)" behavior wording. Running it against the real implementation (GREEN step) failed: h5py constructs a fresh Python wrapper object on every `__getitem__` call, so two separate lookups of the same key are never the same Python object even though they reference the same underlying HDF5 identifier. Verified empirically (`g1 is g2 -> False`, `g1 == g2 -> True`, `g1.id == g2.id -> True`) before rewriting the assertion to `==` plus an explicit `.id ==` check, which is the correct way to express "same underlying object, not a copy" for h5py. This is a test-authoring correction, not a plan deviation — the helper's actual behavior (return the object from `parent[key]` unmodified) is exactly what the plan specified.
- **`_compute_reproj_stats` whole-number finding (Task 3, required by plan's `<output>` spec):** Read before coercing. `n_fish_frames` is a Python `int` counter incremented via `+= 1`; `n_residuals` is `len(all_residuals)`, also always a Python `int`. Neither key can hold a fractional value. The `int()` coercion at the two `reproj_before.get(...)` retrieval sites is therefore lossless — no rounding, no truncation of real data. **Serialization consequence:** `SmoothingMetrics.to_dict()`'s `reproj_n_fish_frames`/`reproj_n_residuals` keys were already declared `int` on the dataclass and were never actually emitting a fractional JSON number at runtime (Python's `int`/`float` duck-typing meant the old code path worked correctly despite the static type mismatch) — this fix closes a *static* type gap, not a runtime *behavior* change. No test asserts a float shape for these keys, so D-06's stop-and-surface trigger did not fire.
- **`cast()` sites left untouched, as scoped.** No `cast(h5py.Dataset, ...)` / `cast(h5py.Group, ...)` site in `core/stitching.py` or `core/reid/swap_detector.py` was touched or converted — this plan only modified `smoothing.py`, which had no pre-existing `cast()` calls. The two-idiom inconsistency named in the plan's `<design_decisions>` remains exactly as scoped for `113.2-06-PLAN.md` to document as a follow-up.
