<objective>
Correct the two known factual errors in the Zenodo tutorial deposit — in **both**
the generating templates inside `scripts/package_tutorial_dataset.py` and the
extracted `aquapose-tutorial-data/` tree (D-05, D-06) — verify every remaining
command the deposit tells a user to run against the real CLI, add regression
tests, and re-emit the checksum manifest.

This must land before Plan 06 mints the DOI. A published Zenodo record is a
permanent public artifact: a mistake requires publishing a corrected *version*
while the original DOI keeps resolving to the flawed files forever. That is why
D-04 sequences D-05 ahead of the upload.

Purpose: DOCS-07 (the tutorial is written against this deposit) and DATA-01
(the packaging script is the reproducibility claim).
Output: corrected templates, corrected tree, new regression tests, and a
re-emitted 22-file checksum manifest that verifies clean.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deposit README → reader's shell | Every command in the deposit README is copied and executed by a stranger on their own machine. A wrong command wastes their time; a command pointing at the wrong repository sends them somewhere the project does not control. |
| deposit tree → permanent public record | After Plan 06 these files are immutable under a DOI. Correctness here is a one-way gate. |
| checksum manifest → downloader | `checksums.sha256` is the only integrity signal a downloader has for the 215 MB deposit. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-113-08 | Spoofing | `aquapose-tutorial-data/README.md` repository link | high | mitigate | The deposit points readers at a GitHub org that is not the project's. An unclaimed or third-party-controlled namespace at that address could serve arbitrary code to anyone following the citation. Task 1 and Task 2 replace it with `McGrathLab/AquaPose` in both the template and the tree before publication. |
| T-113-09 | Tampering | `aquapose-tutorial-data/checksums.sha256` | high | mitigate | A stale manifest silently stops verifying the files it names. Task 2 re-emits it with `write_checksums` after the corrections and gates on a 22/22 `sha256sum -c` pass. |
| T-113-10 | Information disclosure | `aquapose-tutorial-data/config.yaml` | medium | mitigate | `verify_deposit` check (b) fails the deposit if the config contains a `/home/` or `D:\` substring; Task 2 runs it and requires an empty problem list, so no local username or Windows path can leak into the public record. |
| T-113-11 | Tampering | transient artifacts in the shipped tree | medium | mitigate | `finalize_deposit` removes `geometry/luts/` and `reference_outputs/run_*/` before checksumming, so ~597 MB of machine-specific transient data cannot be published or hashed into the manifest. |
| T-113-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install task exists in this plan. `pip install aquapose` appears only as documented prose inside a template string and is never executed. |

ASVS level 1; blocking severity: high. T-113-08 and T-113-09 are both mitigated within this plan.
