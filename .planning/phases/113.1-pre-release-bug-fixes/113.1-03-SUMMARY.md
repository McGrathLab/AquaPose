## Decisions Made

- Placed the spline/t-range/observed-keypoint content in Stage 5 (Reconstruction), not Stage 2 (Pose), because that is where `_keypoints_to_midline` actually implements it — `core/pose/backends/pose_estimation.py` accepts `keypoint_t_values` as a constructor parameter but never stores or reads it (verified via `grep -n "_keypoint_t_values" pose_estimation.py` returning no hits). The plan's `<action>` text suggested folding this content into the Pose subsection under "the pose path" framing; verifying against source showed the implementation lives one stage later, so it was placed there instead — the standing lesson this phase exists to enforce ("verify against source, not against another document") applies equally to a planner's own action text when source disagrees.
- Removed the current-guidebook's Association "emits `handoff_state`" / "accepts `prior_context`" claims rather than merely renumbering them, because `grep` found zero references to either name (or to `ChunkHandoff`) anywhere in `core/association/stage.py`. `ChunkHandoff` is a `TrackingStage` concern (`core/tracking/stage.py:15,65,141-149`), consistent with the guidebook's own separate `### CarryForward` subsection, which was left unchanged as still accurate.
- Split Task 3's todo-filing into two commits (`0f31812` pure `git mv`, `a652dbe` content edit) instead of one, so `git log --follow` traces a clean 100%-similarity rename rather than relying on git's rename-detection heuristic correctly pairing a heavily-edited file across paths (it did not, on the first attempt — content added to the moved file dropped below the ~50% similarity threshold `git status`/`add -A` use).
