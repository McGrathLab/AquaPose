<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository → downstream users | the declared license is a legally binding grant; once published it cannot be walked back |
| `LICENSE` file → GitHub / PyPI license detectors | automated consumers hash the license body; mangled text silently misreports the license |
| `pyproject.toml` metadata → PyPI | the license field is what a future release publishes as the package's legal terms |
| local commits → `origin/dev` → `release.yml` | pushing triggers `semantic-release version`, which can tag a release |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-108-06 | Repudiation | published license grant (irreversible once released) | mitigate | The relicense is confined to a documented, user-decided scope (D-07..D-11); D-10's boundary note records that v1.1.1's MIT grant stands, so no reader can be misled into thinking a prior grant was revoked; the exact SPDX string and copyright holder are pinned verbatim rather than paraphrased |
| T-108-07 | Spoofing | license misattribution | mitigate | Copyright holder string is asserted byte-exact by acceptance criteria; `grep -c 'tlancaster6' LICENSE` must return 0 so the GitHub handle never stands in for the legal holder |
| T-108-08 | Tampering | canonical AGPL text integrity | mitigate | LICENSE body is fetched from `gnu.org/licenses/agpl-3.0.txt` and asserted to contain the exact title and version-date lines with a ≥600-line floor; the action forbids reflowing or reindenting |
| T-108-09 | Information Disclosure | metadata inconsistency between `LICENSE`, `pyproject.toml`, and README | mitigate | Acceptance criteria assert `grep -c 'MIT'` returns 0 in both `pyproject.toml` and `LICENSE`, and that the README no longer links `[MIT](LICENSE)` |
| T-108-10 | Elevation of Privilege | `release.yml` cutting a tag against an MIT tree | mitigate | Every task ends with "do not push"; the phase's single push is deferred to plan 108-05, after this plan's commits exist |
| T-108-11 | Denial of Service | build backend rejecting PEP 639 SPDX string + OSI classifier together | mitigate | Task 1 gates on `hatch project metadata` exiting 0 and specifies an explicit deterministic fallback to the `{text = ...}` table form |
| T-108-SC | Tampering | npm/pip/cargo installs | accept | No package is installed by this plan; `hatch project metadata` reads existing metadata and does not resolve new dependencies |
</threat_model>
