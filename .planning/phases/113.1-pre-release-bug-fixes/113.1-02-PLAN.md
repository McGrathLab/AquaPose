<objective>
Make the first command a new user runs produce a config that fails *correctly*.

Today `aquapose init` writes a string `n_animals` sentinel and `load_config`
compares it numerically, so an unedited scaffold crashes with a TypeError from
inside the validator instead of the actionable ValueError the validator was
written to raise. Both halves get fixed (D-12): the generator writes an int and
keeps the instruction as a YAML comment, and the guard type-checks before
comparing so a hand-edited config cannot reintroduce the crash. The missing
next-step that let a user hit this at all is added as step 1 of the post-scaffold
guidance (D-13).

Purpose: QA-05 success criterion 3.
Output: an `init` scaffold that fails closed with a teachable message, and a
guard that holds for values the scaffold never writes.
</objective>
