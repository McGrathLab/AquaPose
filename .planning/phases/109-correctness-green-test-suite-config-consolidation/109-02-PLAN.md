Make `store.assemble()` resilient to a missing symlink privilege (the real Windows
hot-path break: `data assemble` dies with WinError 1314 when Developer Mode is off).
Per D-09 (Option A, user-confirmed), try `symlink_to` → fall back to hardlink
(`os.link`, same volume, no data duplication) → fall back to copy (`shutil.copy2`)
only when cross-volume. Update `test_symlinks_are_relative` semantics accordingly, and
fix the deterministic-ordering flake in `list_models` (cluster 6). This closes 14 of
the 23 baseline failures plus the ordering failure.

Purpose: Real users on stock Windows must be able to assemble training datasets; the
CLI must not depend on an elevated privilege. This is the largest single fix.

Output: `store.assemble()` with a three-tier link strategy; `list_models()` with a
stable sort; `test_symlinks_are_relative` asserting "symlink when privileged, else a
valid hardlink/copy pointing at the right content"; the 14 assemble tests + the
ordering test green.
</objective>
