## Approach decision — Option 3, on evidence

CONTEXT.md leaves the choice to Claude's discretion and says to prefer the
todo's Option 1 (caller resolves the video paths and passes them in) "unless
reading the code shows otherwise." Reading the code shows otherwise.

`VideoFrameSource` has ten construction sites, and three of them are inside
`core/` itself: `core/reid/swap_detector.py` line 375, `core/reid/miner.py` line
658, and `core/reid/runner.py` line 225. All three receive a `video_dir` string
from a run config. Under Option 1 those three modules would have to call
`discover_camera_videos` themselves, which means importing `aquapose.io` from
`core/` — the violation is relocated from one core module to three, and the
success criterion ("`core/` imports only stdlib, third-party, and core
internals at runtime") is measurably further from true than before.

Option 3 is therefore taken: `discover_camera_videos` is pure `pathlib` (see
`src/aquapose/io/discovery.py`, whose only import is `pathlib`), it has exactly
one importer in the whole tree, and GUIDEBOOK section 3 already describes the
kind of work it does as Layer 1. Moving it into `core/` fixes the layering with
zero call-site churn and no signature change.

## Flagged assumption (carried, not silently accepted)

CONTEXT.md states that `core/types/frame_source.py:25` is "the only module-level
runtime violation (verified 2026-09-02)." Reading the tree during planning found
a **second** module-level, unguarded violation:
`src/aquapose/core/reid/cli.py:9` — `from aquapose.cli_utils import get_project_dir, resolve_run`.
There are also three function-local imports of `aquapose.training` from
`core/reid/` (`cli.py:267`, `cli.py:434`, `swap_detector.py:323`), which execute
at runtime and so also fall under the success criterion's wording.

This is exactly the class of drift the phase's standing lesson warns about, and
the planner is not authorized to widen scope to fix it (D-02 fences the phase to
the one named import-boundary todo). It is therefore **carried as a flagged
assumption**: the guard test allowlists these entries with an explicit annotated
reason, and Task 2 files a todo so the exemption has a tracked home rather than
becoming permanent by silence. If the executor's own AST scan surfaces further
violations beyond those listed here, allowlist and record them the same way —
never silently, and never by fixing them in this phase.
