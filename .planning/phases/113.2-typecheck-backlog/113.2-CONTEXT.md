## Implementation Decisions

### The error distribution, measured rather than assumed

The originating todo describes the backlog as "perhaps 6-10 underlying issues" across
`core/reid/runner.py`, `evaluation/stages/smoothing.py` and `training/reid_training.py`.
**That file list is incomplete and the proportions are wrong.** Measured 2026-09-02 by
running `hatch run typecheck` and grouping its output:

| File | Errors |
|---|---|
| `evaluation/stages/smoothing.py` | 43 |
| `core/reid/runner.py` | 27 |
| `core/stitching.py` | 12 |
| `core/reid/swap_detector.py` | 7 |
| `training/reid_training.py` | 5 |
| `evaluation/stages/reconstruction.py` | 1 |
| `evaluation/runner.py` | 1 |
| `core/reid/cli.py` | 1 |
| `core/reconstruction/backends/dlt.py` | 1 |

`core/stitching.py` (12 errors) is **not mentioned in the todo at all**, and
`smoothing.py` is the largest cluster rather than a minor one. Re-measure before
planning against these numbers — they are a snapshot, and 113.1 changed source.

- **D-01:** Treat this as **one dominant cluster plus a short tail**, not 98 independent
  errors. Roughly **89 of 98** trace to a single root cause (see D-02). The remaining ~9
  are genuinely separate and small.

### The dominant root cause

- **D-02:** h5py's `Group.__getitem__` / `File.__getitem__` returns the union
  `Group | Dataset | Datatype`, and the code indexes straight through it without
  narrowing. Verified at `evaluation/stages/smoothing.py:106`:

  ```python
  with h5py.File(str(smoothed_path), "r") as f:
      grp = f["midlines"]              # -> Group | Dataset | Datatype
      centroid_z = grp["centroid_z"][:]  # error: __getitem__ not defined on Datatype
  ```

  This single shape produces every one of these rule violations:
  `reportIndexIssue` (40), most of `reportArgumentType` (35 — the union passed where
  `NDArray`, `ConvertibleToInt`, `ConvertibleToFloat` or `Sized` is expected),
  `reportAttributeAccessIssue` (12 — `.shape` on `Group`/`Datatype`), plus the
  `reportCallIssue` and `reportOperatorIssue` hits.

- **D-03:** Fix it with a **typed narrowing helper**, applied at each read site. There is
  an existing precedent in the codebase — `src/aquapose/cli.py:877,882` uses
  `assert isinstance(cp_ds, h5py.Dataset)` — but prefer a helper function over bare
  `assert` for new sites, because `assert` statements are stripped under `python -O` and
  would silently remove the check in an optimized run. The helper should raise a real
  exception with a message naming the key and the file.

- **D-04 (placement constraint):** The helper must be importable by `core/`,
  `evaluation/` and `training/` alike. `core/` may only import stdlib, third-party and
  core internals — a constraint now enforced by the AST guard
  `tests/unit/core/test_import_boundary.py` added in 113.1-04 — so the helper must live
  under `core/` (everything else may import downward into it). Do not put it in `io/`
  or `evaluation/`; that would either break the boundary or be unreachable from
  `core/stitching.py`.

### Scope and mode

- **D-05:** Fix at root cause. **No blanket `# type: ignore`.** A targeted, commented
  ignore is acceptable only where the error is a genuine third-party stub defect, and
  each such case must name the library and the reason inline.
- **D-06:** Behavior must not change. This phase edits annotations, adds narrowing, and
  corrects genuinely wrong parameter types. It does not restructure logic. Any place
  where correct typing *reveals* a real bug should be surfaced explicitly rather than
  silently fixed — a type error that turns out to be a live defect is a finding worth
  its own decision, not a quiet edit.
- **D-07:** `typeCheckingMode` stays **`basic`** (`pyproject.toml [tool.basedpyright]`)
  for this phase. The originating todo asks whether to tighten it once green; that is a
  separate decision to record, not to act on here. Reaching 0 under `basic` is the goal.

### The short tail (~9 errors)

- `training/reid_training.py` — 4 errors where `float` is passed to `int`-annotated
  parameters `alpha` / `beta`; the annotations are wrong, not the call sites. Plus 1
  where `_EmbedderConfig` fails the `ReidConfigLike` protocol: the protocol declares
  writable attributes while the frozen dataclass provides read-only ones, so the protocol
  should declare read-only properties.
- One each of `reportRedeclaration`, `reportOptionalMemberAccess`,
  `reportGeneralTypeIssues`, `reportAssignmentType`. The `reportOptionalMemberAccess` in
  `core/reid/swap_detector.py` (`"shape" is not a known attribute of "None"`) is the one
  most likely to be a **real latent bug** rather than a typing gap — treat it as such
  until proven otherwise.

### Claude's Discretion

- How to split the work across plans and waves. The natural seam is the h5py helper first
  (it must exist before any call site can use it), then the per-file application, which is
  parallelizable by file since the five files do not overlap.
- The helper's exact name, module, and signature.
- Whether to also apply the helper at the two existing `assert isinstance` sites in
  `cli.py` for consistency. Not required — they already typecheck.

</decisions>

<specifics>
## Specific Ideas

**The trap in this phase is that a green typecheck is trivially achievable and almost
worthless if reached the wrong way.** `# type: ignore` at 98 sites, or widening
annotations to `Any`, both produce `0 errors` while removing the only signal that made
the backlog worth clearing. Two guards against that:

- Any solution whose diff is dominated by `type: ignore` comments or `Any` annotations has
  failed, regardless of the error count.
- The count must reach 0 **and** the suite must stay at 1403 passed with no test modified
  to accommodate a type change. If a test needs editing to keep passing, the change was a
  behavior change, not a typing change — stop and surface it.

Standing lesson carried from Phases 113 and 113.1: **verify against source.** The todo's
own file list for this backlog was incomplete (it omits `core/stitching.py`, 12 errors),
which is the fourth time in three phases that a planning document has disagreed with the
code. Re-measure; do not plan against the numbers in this document without re-running
`hatch run typecheck` first.

</specifics>
