## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-114-01-01 | Spoofing | `CODE_OF_CONDUCT.md` enforcement URL | mitigate | The old `tlancaster6/aquapose` name is now free for anyone to register. GitHub's redirect only persists while the old name is unclaimed; if a third party claims it, abuse reports would route to a stranger's issue tracker. Task 1 replaces it with the literal `https://github.com/McGrathLab/AquaPose/issues` and the verify gate asserts zero remaining `tlancaster6` occurrences outside CHANGELOG. |
| T-114-01-02 | Tampering | `docs/contributing.md` clone URL | mitigate | A `git clone` URL pointing at a reclaimable name is a supply-chain vector — a contributor could clone and build an attacker-controlled tree. Same fix and same verify gate as T-114-01-01. |
| T-114-01-03 | Repudiation | `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md` | mitigate | Deleting criterion 3 / README-03 would erase the record that a requirement was consciously deferred, making later verification unable to distinguish "deferred by decision" from "silently dropped". The prohibitions in `must_haves` and the acceptance criteria both assert the original text survives verbatim. |
| T-114-01-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no packages. No package-manager invocation is in scope, so the supply-chain legitimacy gate does not apply. |

CHANGELOG.md's ~829 historical `tlancaster6` links share T-114-01-01's shape but are dispositioned **accept** per D-13: they are a historical record of links that were correct when written, they are not instructions a visitor acts on, and rewriting history-of-record to chase a rename is worse than the residual risk.
