## Follow-up Finding (per plan `<output>` spec)

**`stitching.py:563` `if points is None:` is unreachable after this plan's narrowing.** `require_dataset(...)` either returns an `h5py.Dataset` or raises `TypeError`/`KeyError` — it never returns `None`, and the immediately following `[:]` subscript produces a numpy `ndarray`. The guard was defensive code written against the pre-narrowing return type (`Group | Dataset | Datatype | Unknown`, which could plausibly have looked `None`-like to a reader, though never actually `None` at runtime either — `f["midlines"]["points"]` raises `KeyError` on a missing key, it does not return `None`). No behavior changes today since the guard was already dead in practice; it is now dead in a way basedpyright itself can observe (`reportUnnecessaryComparison` would flag it under a stricter mode). Recommend a future todo remove it once `typeCheckingMode` is reconsidered per D-07's deferred decision, since removing it now — while behaviorally inert — is a logic edit this phase's scope excludes.
