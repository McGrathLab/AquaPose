## Decisions Made

- **No `src/` change was needed.** Both `format_obb_annotation` (`src/aquapose/training/geometry.py:307-337`) and the label-file write `"\n".join(cam_obb["obb_lines"]) + "\n"` (`src/aquapose/training/pseudo_label_cli.py:480`) were re-verified against source during this plan and confirmed correct: two OBB objects detected in one image are written as two lines, which is correct YOLO OBB format. The defect was entirely in the test's own assertion.
- **The float `0.0` class token was investigated and deliberately left alone**, for two independently-verified reasons:
  1. Ultralytics 8.4.28 parses the class column as `np.float32` (`classes = np.array([x[0] for x in lb], dtype=np.float32)` in `ultralytics/data/utils.py::verify_image_label`), so a float class token is not a parsing hazard.
  2. Every human-labelled file in the real training corpus already uses `0.0` as its class token — checked across `~/Downloads/pose/datasets/pose_ablation_a_manual/labels/train` and `~/Downloads/pose/datasets/round1-curated/labels/val`, both of which trained successfully. `0.0` is the established on-disk convention for this project, not a bug.
- **Test-command scoping note (per plan's own critical reminder):** the plan's acceptance criterion phrasing `hatch run test tests/unit/training/test_pseudo_label_cli.py` does not scope pytest collection to that file — the hatch script is `pytest tests/ -m "not slow" {args}`, so the path argument is appended to `tests/` and the entire suite still runs (confirmed: both the "scoped" and unscoped invocations produced identical `1400 passed, 3 skipped, 17 deselected` results). The criterion is still satisfied (the target file's tests are included in that run), but for genuinely targeted single-test runs, `hatch run test -k <test_name>` (used for the non-vacuity probes below) is the correct form. Flagging this so the phrasing is corrected in future plans rather than silently misleading a future reader.
